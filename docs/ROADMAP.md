# Roadmap

What exists, what does not, and what comes next. The point of this page is that
the second list is honest.

## What works today

- One compiler over five materially different jobs — a refund desk, an
  accounts-payable queue, a sales pipeline, an IT access register and a
  warehouse — with no branch on which workflow it is looking at, and a build
  check that fails if a business noun appears in generic code.
- A sixth domain, written only inside a test file and never seen by product
  code, compiles and generates a working suite with no changes.
- Recording from a browser, an action log or a hand-written import, all
  normalising to one trace.
- Rules induced from the state delta, the declared schema and the text the
  operator could see — carrying typed provenance and a plain-English question.
- A rule that RigorRun guessed cannot fail an agent until a person says yes.
  Saying no keeps the rule as a control rather than deleting it.
- Cases generated by mutating the world: boundaries at the declared precision,
  missing links, records made to disagree, lifecycle states nobody
  demonstrated, hostile text in the fields an outsider can write to.
- Expected outcomes computed by replaying the demonstrated job against each
  mutated world, never written down.
- The benchmark graded before any agent is: false positives, whether cases
  separate anything, injected defects, a control that must survive, replay
  stability, hidden-answer isolation.
- Rules the environment enforces itself are found by trying the violation, and
  dropped rather than left in to flatter the result.
- An environment SDK with a conformance kit, and a scaffold command.
- An HTTP agent protocol and an OpenAI-compatible adapter.
- A CLI whose exit codes are a usable CI gate, and a self-contained report.

## What is honestly not built

**No browser execution lane.** Agents call a typed action API. The assertion
kinds for DOM and HTTP exist and are tested, but nothing drives a real browser,
so an agent that only works by clicking cannot be tested. This is the largest
single gap.

**Every environment is synthetic.** The SDK is real and conformance-checked. No
third party has pointed it at a staging system, so the thirty-minute claim in
`CONNECT_ENVIRONMENT_30_MINUTES.md` is a design target, not a measurement.

**The reference implementation is an oracle.** It is given the answer. It
proves the suite is satisfiable and nothing else.

**Cross-demonstration recall is not measured.** The strongest available check
on whether induction generalises is to record the same job twice and see which
rules recur. The machinery exists; the second recordings do not.

**No model-judged evaluator.** The type, the label and the report treatment
exist. The evaluator does not, deliberately.

**Induction over-produces.** RigorRun proposes more rules than most reviewers
will want, on the principle that saying no is cheaper than missing one. Roughly
a quarter of confirmed rules turn out to be decisive on the generated cases;
the rest are satisfied by everything. That number is on `/proof`.

**One recording, one contract.** Rules come from a single demonstration, and
the weakest of them come from a regular expression reading a number off a page.
Both are reported, neither is fixed.

**No multi-user control plane, and reports are not signed.**

## Next

### Near term

1. **Playwright execution lane.** Same cases, same checks, driven through a
   real UI, with verification still going through the adapter rather than the
   DOM.
2. **A second recording per workflow**, and cross-demonstration recall as the
   headline generalisation number.
3. **Rule consolidation.** Three-quarters of confirmed rules never decide
   anything. Merging or dropping them at compile time would make review
   shorter and the suite sharper.
4. **Importing a policy document** so a threshold has better provenance than a
   sentence on a page.

### Medium term

5. **Regression tracking.** Which case started failing, on which agent version.
6. **A model judge, properly.** Never as arbiter: a second opinion that can
   only flag a deterministic PASS for human review, never overturn a FAIL.
7. **Signed reports.**
8. **A recorder that is not Chrome-only.**

### Longer term

9. **The independent verification layer for AI labour.** The unit of trust in
   agent procurement should be "verified against the buyer's own workflow", not
   "scored well on a public benchmark".
10. **Portable workflow contracts** a buyer can hand to three vendors.
11. **Continuous verification** on every agent update.

## Explicitly not planned

- A public model leaderboard. The value is that the benchmark is private.
- Production trace ingestion as the primary input. Working *before* there is
  traffic is the whole idea.
- A model that writes test cases.
- Production observability. Different product, different buyer.
- An agent framework.
