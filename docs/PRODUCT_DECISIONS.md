# Product decisions

What was decided in the 10 September 2026 due-diligence pass, and why. Reasons
rather than conclusions, so a later reader can disagree with the reasoning
instead of guessing at it.

---

## `npx rigorrun` stays the front door; `rigorrun verify` is the second act

**Decided:** the hero keeps `npx rigorrun`. `verify` gets its own section
immediately below, with the real terminal output of a real run.

`verify` is the better *demonstration*: one command, no project, no browser, no
agent, a real result in fifteen seconds against software we did not write. The
argument for making it the hero is strong.

It needs Docker. A hero command that exits 2 for every visitor without a running
daemon is worse than one extra step for the visitors who have one. So the page
leads with the command that always works and puts the more impressive one where
somebody who has Docker will find it in five seconds, with the requirement
stated rather than discovered at an error message.

**What would change this:** if `verify` gained a runtime that is present by
default — or if measurement showed most visitors have Docker — it should lead.

## `/proof` deleted rather than relabelled

**Decided:** the five-workflow page is gone. `/#/evidence` replaces it, built
from four real third-party servers. `#/proof` still resolves there.

The numbers on that page were real output of the real pipeline and could be
regenerated by a script, so nothing on it was fabricated. But it was headed
**EVIDENCE**, it named five companies — Northstar Support, Meridian Finance,
Kestrel CRM, Lattice IT, Harbourline Ops — and it carried agent leaderboards.
Five company names under that heading reads as five real deployments. Relabelling
it would have left the strongest visual real-estate on the site arguing for a
thing that had not happened.

The replacement makes a smaller claim and can support it: four servers, one
publisher, 51% of tools exercised, and a paragraph saying what that does not
establish.

**Rejected:** keeping it under a "Synthetic" heading. The page's whole rhetorical
shape — five disciplines, five companies, a comparison table — is an argument
about breadth of validation. Labelling does not undo shape.

## The example is kept, demoted, and labelled

**Decided:** the in-page demo stays, off the navigation and off the hero, in a
panel headed **Synthetic example**.

It is the only thing on the site that shows the whole idea to somebody who has
installed nothing, and it executes the shipped packages rather than replaying a
recording. Deleting it would have cost more than it saved. What it could not keep
was the position: two of two navigation items and the second hero button all led
into it, so the honest reading of the old site was that the product *was* the
demo.

The word "synthetic" appeared exactly once on the whole site. It now appears
wherever somebody is looking at invented data.

## No SDK will be published

**Decided:** confirmed, not revisited. `@rigorrun/agent-sdk` stays private.

The agent protocol is plain HTTP and about ten lines. Publishing a package to
save ten lines creates a version-compatibility surface between a customer's agent
and their test harness, which is exactly the coupling the Python SDK avoids by
being standard-library only. `docs/TYPESCRIPT_AGENT_SDK.md` already said it was
not on npm; the README table now says so too.

## `DECLARED` added rather than removing the isolation label

**Decided:** a fourth isolation level, meaning "configured and never checked".

The alternative was to keep three levels and measure the reset on every run —
correct, and expensive: it means running the operator's reset tool twice and
diffing their system before any case executes. `verify` can afford that because
it owns a container. A run against somebody's staging box cannot assume it.

So the type now distinguishes what was performed from what was promised.
`RESET` where the reset is RigorRun's own machinery, `DECLARED` where it is a
tool somebody nominated. This is the same distinction the codebase already drew
in prose — "the only reset kind that is a property of our own machinery rather
than a promise made by somebody else's system" — now enforced by the type.

## `gate --agent reference` refused rather than removed

**Decided:** `gate` rejects the reference implementation unless
`--allow-reference` is passed.

Gating on an oracle that is handed the answer is a guaranteed pass, and it was
the documented example. But "is this suite satisfiable at all?" is a real
question, and the answer is exactly that run — our own CI asks it. Deleting the
capability would have removed a useful check to prevent a misuse. Making the
misuse impossible to reach by accident costs one flag.

## The synthetic demo still ships inside the npm package

**Decided:** keep it. Reversed from the initial plan.

The concern was that `DemoPage-*.js` is the largest file in the tarball and is
marketing rather than product. Two things make it worth keeping: it is
lazy-loaded, so it costs a local user nothing until they open it; and the local
runner offers it as a bundled example, which is a genuine onboarding affordance
for somebody who has just installed and has nothing connected yet. The packed
artifact is 350kB against a 600kB budget, so nothing is being crowded out.

## The orphaned Cloudflare Worker was left running

**Decided:** documented, not deleted. Teardown was not authorised in this pass.

It is a live, publicly reachable endpoint branded with the product, whose source
was deleted in `b1e121c`, still bound to an empty D1 database. Nothing shipped
calls it — checked, by grepping the published CLI bundle and the deployed site
bundle for its address. So it is an orphan rather than a leak.

It should still go, and the exact commands are in `CLOUDFLARE_READINESS.md`.
Deleting infrastructure on somebody's live account is not a decision to take
because it seemed tidy.

## Provenance over prose for every public number

**Decided:** a number on a public page must be generated by a script that can be
re-run, or it does not go on the page.

`proof.json` had this and the gate protecting it was broken in two independent
ways, so it drifted 13 commits while claiming to be current. `evidence.json` has
it and records more: the RigorRun version, the Docker version, the commit, the
registry digest of every artifact measured, and the base image.

The corollary is the rule that produced most of this document: **do not write a
number into prose that was not read from an output.** Four documented facts
failed that test and were corrected against `curl` and a test run.
